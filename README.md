# Eddies War Room

Private pages for the Eagle Ridge Eddies. Two screens:

- `index.html` is the in-season War Room: this week, weekly rankings, roster, waivers, IDP, news, the league, and the trade calculator.
- `draft.html` is the draft board. `draft-archive.html` is the 2026 draft-day copy and stays as it was.

Eddie fills `data/warroom.json`, `data/free-agents.json`, and `data/green-dots.json`. How those files are shaped:

- [docs/warroom-schema.md](docs/warroom-schema.md)
- [docs/free-agents-schema.md](docs/free-agents-schema.md)
- [docs/draft-setup.md](docs/draft-setup.md)
- [docs/rankings-schema.md](docs/rankings-schema.md)
- [docs/green-dots-schema.md](docs/green-dots-schema.md)
- [docs/sunday-command-center.md](docs/sunday-command-center.md)

To rebuild trade prices from the season's stat lines, run `python3 scripts/build_player_values.py` from this folder. The Trade tab reads `data/player-values.json`.

To rebuild the weekly rankings board, run `node scripts/build_rankings.js` from this folder. A scheduled action does that through the week and commits `data/rankings/`.

To rebuild the ROS trade ideas, run `python3 scripts/build_trade_finder.py` from this folder. It writes `data/trade-finder.json` for `trade-finder.html`. The list is ideas only. It does not send trades or contact Fantrax.

`sunday.html` is the phone page for Sunday. It reads `data/sunday/config.json`, `data/sunday/live.json`, and `data/td-parlay.json`. A separate job is meant to refresh the live file about every 30 minutes. The page refetches every 5 minutes. It does not scrape.

## Auto-refresh (branch `eddie/warroom-auto-refresh`; merge is Bill's)

Nothing here pushes to `main`, and nothing here pushes at all. Bill reviews and merges.

- `data/season-ending.json` lists players out for the year (seeded with Edgerrin Cooper, LB GB, Achilles, IR since Oct 13 2026). They are removed from waiver recs AND the FA pool. **Required**: if this file is missing, invalid or empty, the run fails. A seed floor in code (`REQUIRED_SEASON_ENDING` in `scripts/warroom_common.py`, currently Edgerrin Cooper) must be on the list, or the run fails, so a wiped or truncated list can't fail open.
- `data/do-not-pitch.json` lists Bill's passes (for example Austin Booker for Week 7). They are removed from waiver recs only and stay in the FA pool. A pass applies only to the week(s) in `weeks` (missing/invalid `weeks` = only the week of `since`); the player is eligible again the next week. Only season-ending entries are permanent. **Required** and fail-closed. It MAY be empty, but only as the explicit object `{"players": []}`. A missing file, `{}`, `null`, or a bare array fails.
- Name matching (token based): a name is split into letter-only tokens on any non-letter (`|`, comma, period, parens, dash, `_`, digits), apostrophes are dropped first (Ja'Marr stays one token), and known team, position and status codes (GB, LB, IR, ...) plus Jr./III are dropped. An excluded player {first, last} matches when the tokens equal {first, last} in any order, or when his last name is present with his first name or first initial. Ids (`id`/`ids` on a list entry vs `id`/`playerId`/`fantraxId` on a rec) match too. "Edgerrin Cooper|GB", "Cooper E.", "Cooper, Edgerrin (LB-GB)" and "EDGERRIN  COOPER" are blocked. Darius, Amari, Eric and Ed Cooper and Cooper DeJean are kept. A rec with fewer than 2 name tokens (id-only or null name) is never published. A code token that is part of a real player's name found in `data/` roster/player files is kept (KC Concepcion keeps `kc`, Jordan van den Berg keeps `den`). All names are NFKC-normalized with format characters (zero-width U+200B-U+200D, U+2060, U+FEFF, soft hyphen) removed first; a name with any non-Latin letter (e.g. a Cyrillic `о` in "Edgerrin Cоoper") is unidentifiable and never published, and in a waiver rec it stops the run.
- Pending gate (fail closed):
  - **Strict sections** (`waivers`, `trades`, `drops`, `bids`, `claims`): only allowlisted keys per section. A record passes only with no status (recommendation rows) or a completed status (completed/processed/executed/accepted-and-processed). Bids and claims must carry a completed status. `status: null`, a number or `""` blocks. Free text blocks only on WHOLE pending words or status phrases (pending, PEND, awaiting, Countered, counter offer, submitted, proposed/proposal, in/under/league review, in_review, in queue, trade offer / offer sent / made an offer, outstanding bid/claim, still outstanding), never on fragments: suspended, dependent, must-spend, preview, reviewed, encounter, queued, submits, proposition, countering, "not an offer", "0 pending claims", "pending 0/0" all pass. Round 6: "queued claim" / "claim queued", "pended", "waiting on approval", "offer: X for Y" also block (bare "queued" / "queued up" still pass), and accents are stripped after NFKC ("pénding" blocks). Outside those sections the appeal/MRI/results/review-pending exemption applies per sentence and only when that sentence has no bid/claim/trade/FAAB/offer/waiver/$ word ("trade review pending" blocks); a null or empty status in `lineup` or `news` blocks. Any non-Latin letter, any boolean, any object value, or any unknown key stops the run. All 18 past versions of `data/warroom.json` on origin/main pass (tests/fixtures/warroom-history/).
  - **Top level:** any key not in the War Room schema (for example a new `outstanding` list) stops the run. The FA file allows only its schema keys and row fields.
  - **General sections** (lineup, news, injuryWatch...): pending-like keys or `*status` values, `PEND` or "awaiting approval" anywhere, and "pending" next to bid/claim/trade/FAAB/offer/waiver/$N block. A non-string `*status` value (number, boolean, list) blocks; null is allowed. Status values match on word starts, so "Suspended" is fine. Injury/discipline text like "MRI results pending" or "Greenlaw appeal pending" is allowed there; "pending 0/0", "0 pending"/"no pending" is fine.
  - Any hit: nonzero exit, nothing written.
- `scripts/build_free_agents.py` and `scripts/build_warroom.py` pick the newest Fantrax file by its own scrape timestamp (`scrapedAt`/`scraped`), not its file name. Partial scrapes and timestamps in the future are skipped. Week = 1 + floor((today PT − Sep 10 2026) / 7). Stamps are in PT.
- `scripts/refresh_green_dots.py` rebuilds `data/green-dots.json` only from a newer FREE post, and only when all 32 teams are found and every non-bye team is resolved. The post's final current-week wording wins: the LAST "X finished with / took over / took / wore the dot" in a sentence that is not about another time (last year/season/week, previously, in 2025, earlier this season). Every parsed name must be in the repo's player files (IDP rankings, HQ rosters, player-values, the current rankings board, or the previous green-dot list), or that team counts as unresolved. "Bye week? No" is not a bye. A "shared" dot is null with both names in notes. Bye teams get `bye: true`, with the previous dot carried over. It always writes `data/green-dots-status.json` (`stale: true` when the file's week is older than the current week).
- `scripts/refresh_warroom.py --mode full|ci [--dry-run]` copies the repo to a temp stage, runs the steps there, validates JSON, runs the pending gate, then runs the Python and node tests inside the stage. The node whitelist (`tests/KNOWN_FAILING.txt`) matches exact names, nested subtests included, and a node crash counts as a failure. Only then does it swap the staged `data/` in, all-or-nothing. It works in one scratch dir from `tempfile.mkdtemp()` next to `data/`: a full backup copy, a copy of the new data, and the renamed original. It rolls back on error. If the rollback rename also fails, it restores `data/` from the backup and exits 2. If that restore fails too, it prints a loud `!!! DATA RESTORE FAILED` with the paths, KEEPS the scratch dir for manual recovery, and exits 2. **Disk use:** about 3x the size of `data/` (stage copy of the repo in the system temp dir, plus backup and new copies next to `data/`) while it runs. Today `data/` is a few MB. For the instant between the two renames, a reader can find no `data/`. It never commits.
- Times: a `--now` or scrape time with no offset is read as PT. An ambiguous or nonexistent PT wall time (Nov 1 2026 1:00–1:59 AM, Mar 8 2026 / Mar 14 2027 2:00–2:59 AM) fails `--now`, and a scrape file with such a time is skipped. Give an explicit offset (`-07:00`/`-08:00`) instead.
- Routine hook: `bash scripts/hooks/warroom-refresh.sh` after the day's Fantrax scrape and editorial build. If it exits 0, review the diff and commit/push as today. If it exits nonzero, `data/` is untouched.
- `docs/workflows/warroom-saturday.yml` (Bill installs it in `.github/workflows/`) runs Saturday at 10:23 AM PT in `ci` mode. It pushes nothing and opens no PR, and uploads changed green-dot files as a review artifact.
